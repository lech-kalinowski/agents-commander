The Problem

AI agents run in separate terminal sessions.

Coordinating them often means manual handoffs or introducing a separate orchestration layer.

☓

Different Interfaces

Agent CLIs expose different commands and interaction models. Commander provides one local panel interface for its supported adapters.

⛔

Manual Handoffs

Without routing, one agent does not see another session's output. Users must transfer tasks and results between terminals themselves.

⚠

Setup Trade-offs

Framework-based orchestration can add SDKs, runtimes, or configuration. Commander focuses on local terminal sessions and text markers.

The Solution

One terminal. Multiple agents. Text-based routing.

Supported sessions communicate through a simple message format that Commander scans and routes locally.

commander-protocol.txt 
// SEND — direct message to an agent
===COMMANDER:SEND:codex:2:<session-key>===
Write unit tests for src/auth/
===COMMANDER:END:<session-key>===

// REPLY — continue the latest open thread
===COMMANDER:REPLY:<session-key>===
12 tests passing, 0 failing.
===COMMANDER:END:<session-key>===

// BROADCAST • STATUS • QUERY
// 5 commands, fully bidirectional
// SEND/REPLY ACK reports delivery outcome
// BROADCAST ACK reports queue admission
1

Send — Protocol Instructions

Press Ctrl+P to write Commander Protocol instructions directly into the active running agent's terminal session.

2

Scan — Output Monitoring

Commander continuously scans connected terminal output for protocol markers and assembles markers split across streaming chunks.

3

Route — Message Delivery

When a marker is detected, Commander extracts the message and writes it to the target session's input. The receiver sees a new prompt.

Features

Everything you need. Nothing you don't.

A purpose-built terminal UI with working defaults and optional CLI or configuration-file overrides.

▦

Multi-Agent Terminal

Keep up to 100 active file or agent panels in one workspace. Auto density fits the window; manual 2/3/4 density caps each visible page while hidden sessions keep running.

Shift+F4 cycles visible density

Inter-Agent Communication

5 protocol commands: SEND, REPLY, BROADCAST, STATUS, QUERY. Local text routing adds ACKs while each agent CLI handles its own services and credentials.

Architecture

See it in action

Messages move between local PTY sessions as text, with thread and message IDs. REPLY claims the latest open reply window; a delivered ACK means PTY input was submitted, not that the task is complete.

Protocol Message Format
===COMMANDER:SEND:{target_agent}:{panel_number}:{session_key}===
{bounded multiline message content}
===COMMANDER:END:{session_key}===

Fields:   SEND — action  |  codex — target agent  |  2 — stable target panel number  |  session_key — fresh value supplied by Ctrl+P; repeat it in header and footer. Static or stale keys do not route.

Get Started

Choose a release, then launch

Checked 2026-09-02: public npm is v0.1.4; this page describes source v0.1.5. Doctor, conference/demo modes, OpenCode, adaptive density, 100 panels and Codex Micro require the source build. This is a local terminal app, not a browser-hosted workspace.

published npm v0.1.4 (legacy) 
# Install the verified public release
$ npm install -g agents-commander@0.1.4

# Confirm the installed version
$ agents-commander --version

# Legacy layout: 2, 3 or 4 panels
$ agents-commander --panels 2 .

# Also supports --theme and --show-hidden
# No doctor, demo, density or Micro flags
source v0.1.5 checkout 
# In the current source checkout (Node.js 22+)
$ npm install
$ npm run build

# Diagnose the project, then run the offline demo
$ npm start -- --doctor .
$ npm start -- --demo

# Live presentation; use . or your project path
$ npm start -- --conference .

Source requires Node.js 22+, Python 3, and macOS, Linux, or WSL2; npm v0.1.4 advertises Node.js 18+. Get the current source and build instructions. A source push does not publish npm.

F12 Activity is bounded in-memory SEND/REPLY/BROADCAST history; STATUS and QUERY are not in Activity. Ctrl+L opens a rotating diagnostic log, not a full transcript. Source builds support opt-in semantic recording with --capture protocol --capture-project project-01 and reviewed LoRA/SFT dataset export. Recording is off by default; full transcripts, replay and model training are not implemented. Read the dataset guide and broader proposed roadmap.
