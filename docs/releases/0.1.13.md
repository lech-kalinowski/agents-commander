# 0.1.13 release acceptance

Prepared November 9, 2026. Offline verification, both installed-package
Claude/Codex checks and the complete sixteen-agent OpenCode/APEX gate passed.
Registry publication is pending verification below.
This record is separate from the sealed npm archive so its digest and verified
publication status can be added without altering the tested artifact.

## Scope

Release 0.1.13 includes the communication and terminal-rendering repairs on top
of published 0.1.12. It does not include the separate unreleased Codex Micro
framing/diagnostic work, presentations or private QA recordings.

Required gates: full `npm run verify`, real Claude/Codex exact-archive checks in
both layouts, and sixteen-agent OpenCode/APEX baseline, stress and correction
acceptance. Authentication, replay/echo reservations, input-draft guards and
capture consent remain unchanged. No universal model-reliability claim is made.

## Installed-package live checks

Both runs used the global Node 22 installation of the sealed 0.1.13 archive,
not the development checkout or an older registry installation. Real Claude
and Codex CLIs ran in fresh, isolated directories through Commander PTYs,
TerminalPanel, AgentManager, Orchestrator and Blessed. The outer terminal was
a test stream, not a manually operated native terminal window.

- Stacked layout (212 by 66): all eight checks passed.
- Side-by-side layout (200 by 55): all eight checks passed.
- Each run verified three short emoji SEND/REPLY rounds, a continuing six-message
  reply chain on one thread, a 32-line payload, QUERY, STATUS and BROADCAST.
- Each run finished with exactly 15 delivered ledger entries, no duplicate
  routes, model-authored completion markers and an empty Claude ACK composer.
- No rescue Enter, resize or model tool execution was used. Owned sessions
  stopped after each run. Capture remained off; no transcripts or keys were logged.

Codex emitted reserved scroll-region changes during both runs. These particular
CLI runs emitted no CSI REP commands, so REP and emoji stale-cell repair are
covered by deterministic terminal/Blessed regressions, not claimed as freshly
observed live redraw cases. The complete offline gate also exercises the normal
App UI and packed keyboard path; this live pair harness focuses on communication.

## OpenCode/APEX acceptance

The user supplied the current model identifier `callstack/Apex`. A minimal
request to the existing API URL returned HTTP 200 with a model response using
that identifier; the old dated identifier had returned HTTP 403. The local
OpenCode model entries and Commander OpenCode profile were updated explicitly
to `apex/callstack/Apex`. The API URL, token source and other profiles were
unchanged. These private settings are not repository or package contents.

The final run used OpenCode 1.19.5 and the installed, sealed 0.1.13 archive:

- 16 real agent PTYs, native completion-hook IPC and exact session binding.
- 19 baseline/stress trials, plus correction and natural-quit checks, all passed.
- Exactly 22 accepted commands and 72 deliveries; all routes delivered.
- Short, long and Markdown SEND/REPLY/BROADCAST, all five QUERY values and STATUS.
- Concurrent senders, newest/previous reply windows, stable identity after
  reorder, a broadcast to 15 hidden peers, and fresh delivery after resizing.
- One intentional malformed frame produced exactly one correction notice and
  one corrected SEND with a fresh sequence. No incidental or unaccounted notices.
- No input or resize while a trial awaited delivery, no rescue Enter, no
  viewport-routing fallback, no tools, and no raw transcripts or keys logged.
- Native natural quit and complete owned-process cleanup passed. Global
  configuration stayed unchanged during the run; capture was off.

OpenCode's startup model labels were clipped in twelve-row cells. Each of the
16 empty Home prompts was therefore verified in F4 fullscreen before protocol
injection, then restored to the original narrow 351-by-74 matrix. This startup
verification is counted separately from the routing stress checks; it is not
a recovery resize for pending traffic. Strict placeholder/model checks remain.

Final metadata: `baselinePassed`, `stressPassed`, `correctionPassed`,
`fullRunPassed`, `naturalQuitPassed` and `ownedProcessesStopped` were all true.
The final report contains 22/22 commands, 72/72 routes and 16 startup checks.

## Earlier blocked attempts

The first sixteen-agent attempt stopped on the startup recognizer before any
message routing. OpenCode 1.18.31 adds an optional `auto` label to the Home
prompt. The test recognizer now accepts that documented label while still
requiring the empty input placeholder and selected APEX model. Offline tests
reject incomplete prompts and other model labels. This is test-only; the
sealed runtime archive is unchanged.

The second attempt launched all 16 real OpenCode PTYs with native IPC channels
ready, but did not pass protocol setup. Read-only inspection restricted to that
attempt's fresh directory and creation time found 11 owned conversations. Each
contained one submitted user message and one completed assistant API error with
HTTP status 403. The remaining five panels had no bound conversation at the
deadline; successful submission for those five is not established.

No live routing trials ran (0 of the required 22 commands / 72 deliveries).
The baseline, stress, correction and natural-quit checks therefore did not pass.
All owned child processes were stopped and the user's global configuration was
unchanged. No authentication bypass, model substitution, repeated Enter or
viewport-routing fallback was attempted. Publication was held until provider
access and a fresh complete strict acceptance run could be established.

### Credential recheck

Later on November 9, the user entered a replacement token through a masked
local macOS dialog. Only the existing external key file was replaced, with
mode `0600`; the provider configuration was unchanged and the token was never
printed or added to the repository.

The next live attempt stopped at P13's fresh-prompt readiness check before
protocol injection or provider messages. Its native channel was ready, but the
required prompt evidence was absent; this is not a successful startup or routing
test. All owned processes were stopped. A separate minimal request using the
configured APEX endpoint, that key file and `callstack/Apex-20260831` returned
HTTP 403 with an error response. At that point, the new credential had not
established usable access to that model. The HTTP status alone did not identify
the cause. The user subsequently supplied the working model identifier above.

An intermediate run on 1.19.5 completed baseline traffic but correctly failed
the long-receipt checks because the checker did not yet recognize that CLI
version. Source and owned-receipt verification preceded the explicit version
allowlist update. That failed run was not reclassified as a pass; a fresh full
run supplied the final evidence above.

Local metadata-only logs are retained outside the repository in
